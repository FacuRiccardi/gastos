# Web app: expense tables and authentication — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A read-only React app, hosted on Firebase Hosting, where two authorized people sign in with Google and see the stored purchases in one collapsible table per person + card.

**Architecture:** Vite + React + TypeScript app in `web/`, with shadcn/ui, reading Firestore directly from the browser. Access is enforced by Firestore security rules that require the custom claim `household` (set by a local script); the UI only chooses which screen to show. The auth and data layers are injected into the components so they are tested without Firebase.

**Tech Stack:** Vite, React, TypeScript, Tailwind CSS v4, shadcn/ui, Firebase JS SDK (modular), Vitest + Testing Library, `@firebase/rules-unit-testing` + Firestore emulator, `firebase-admin` (script only).

**Spec:** `design/web-app-spec.md` (and the existing ingestion design in `design/spec.md`)

## Global Constraints

- The repository is **public**: never commit emails, project or billing IDs, the Firebase web config, or real purchases. `web/.env`, `web/dist` and `.firebaserc` are git-ignored; docs use `<project-id>` placeholders; all test data is made up.
- The app is **read-only**: no browser write is possible (rules deny every write). Only `expenses` can be read, and only with a verified email and the `household` claim; `state/sync` and everything else is denied.
- shadcn/ui must be installed by following the **official documentation at the time of the work** (https://ui.shadcn.com/docs/installation/vite), not from memory; components needed: accordion (with the `multiple` prop), table, badge, button, card.
- The user's global npm registry points to a private feed, so `web/` needs its own `.npmrc` with `registry=https://registry.npmjs.org/` (the root already has one); check that `web/package-lock.json` has no private-feed URLs.
- Node >= 20, TypeScript strict, English code and docs. **UI strings are in Argentine Spanish and live in one file** (`web/src/strings.ts`).
- Amounts are formatted with `Intl.NumberFormat("es-AR")` as currency; dates are displayed in the `America/Argentina/Buenos_Aires` time zone, whatever the browser's zone is.
- Git commits use the author `FacuRiccardi <FacuRiccardi@users.noreply.github.com>` (as in the existing history, via `git -c user.name=... -c user.email=...`) and end with `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`.
- The existing backend must keep working: `npm test` (root) and `npm run test:store` stay green.

## Review Focus

Failure modes the spec implies that no task's happy-path tests cover; each has a test in the task that owns it.

1. The claim is revoked or expires while the app is open: the Firestore listener fails with `permission-denied` and the UI must show an error message, not crash or show stale data as if it were fine (Task 6, Task 7).
2. The browser is in another time zone (for example UTC): a purchase stored at midnight Buenos Aires time must still display its own day, not the previous one (Task 3).
3. A zero amount (rejected purchase), a very large amount and cents are formatted correctly (Task 3).
4. The login popup is closed or blocked: the login screen shows a message and stays usable (Task 5).
5. An unauthorized or signed-out user must never trigger the Firestore subscription (Task 7).
